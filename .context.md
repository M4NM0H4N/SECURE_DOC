# Project Context (keep < 100 lines; update after each milestone)

**Project:** Secure Document Request and Approval Workflow (SDG 16). `main` + tag `mvp-v1.0` = frozen academic MVP. Branch `saas` = SaaS upgrade (docs/SAAS_PLAN.md, phases S0-S8, one at a time, owner approval at each gate).
**Goal:** Student requests document -> Clerk reviews -> HOD approves/rejects -> Clerk uploads -> Student downloads. RBAC + audit log.

## Stack
HTML/CSS/vanilla JS (ES modules) · Node 24/Express 4 · MongoDB 7 (Docker single-node replica set) + Mongoose 9 · JWT HttpOnly cookie + bcryptjs · express-validator · Helmet · rate-limit · mongo-sanitize · Jest/Supertest. Production target: Render + MongoDB Atlas (prepared, NOT deployed).

## Architecture
client/ (static, served by Express, same origin) -> server/ (routes -> controllers -> services -> models) -> MongoDB + private upload folder (UPLOAD_DIR).

## Key decisions
Clerk + HOD department-scoped · atomic findOneAndUpdate transitions · isActive checked every request · cookie auth + custom-header CSRF · local Docker MongoDB bound to 127.0.0.1 (no auth) · tests only against a LOCAL MongoDB (they drop it) · production DB = Atlas via MONGODB_URI in Render.

## Notes / gotchas
- Jest blocks driver dynamic import('os'); tests pass runtimeAdapters.os in server/tests/helpers.js.
- mongodb-memory-server removed; tests and CI need a real local Mongo replica set (docker compose up -d).
- Never run docker compose down -v (dev data is in ./mongo-data). Never publish MongoDB on all interfaces.
- Tenancy: runAsTenant/runUnscoped await inside the context (a lazy Query returned outside would run unscoped). Tests use a default-tenant fallback (NODE_ENV=test only); tenancy/migration suites turn it off.
- Existing dev DB still holds un-migrated MVP data (dry run: 2 users, 1 request); run npm run migrate:tenants -- --apply when ready.
- Dev uses plain http: HSTS and upgrade-insecure-requests only in production.
